## Убежища

Перенесён VaultDungeon EE: жилые, медицинские, энергетические комнаты, ферма,
оружейная, столовая, диспетчерская, озеленённый зал, высокие залы,
лестничная шахта к входу, большая дверь и спавнеры светящихся.
Новые структуры появляются в новых чанках. По умолчанию вероятность на подходящий
чанк: верхний мир 1/20000, ад 1/1000000; остальные измерения отключены.
Настройка по измерениям: `03.26.1_vaultDungeonSpawn` в конфигурации совместимости.
Для проверки на отдельном мире: `/hbm gen vault_dungeon`. Не применять рядом с ценными постройками.

Дополнительно: независимое состояние каждого отложенного убежища; палитры без
накопления повторов; гарантированная комната входа даже в малом плане;
обновление уже существующего радиационного кэша после строительства.

## Радиация

В Well-Forged уже присутствуют трёхмерное распространение, экранирующие двери,
радиационные карманы и нейтронная активация. Их сохранение не заменено на более
старый код EE: оставлены исправления чтения повреждённых сохранений Well-Forged.
Из EE перенесено недостающее правило экранирования блоками со взрывостойкостью
от 2160000 (включая бедрок). Специализированный интерфейс блока имеет приоритет:
открытая дверь не превращается в экран из-за своей взрывостойкости.

Это перенос экологической модели радиации и убежищ, а не замена всего реестра
опасностей предметов, рецептов и баланса EE. Собственные механизмы Well-Forged сохранены.
`1.31_enableAdvancedRadiation=true` должен быть включён (это исходное значение WF).

## FE и EU

Обычный провод HBM распознаёт внешние энергетические порты; та же проверка
используется для изображения соединения и формы провода.

- HBM → FE: передача в принимающий FE-порт, с его стороны и с проверкой ёмкости.
- FE → HBM: принимающая FE capability провода, сохраняемый буфер 1000000 FE;
  также опрос соседнего чистого источника FE.
- HBM → EU: прямой соседний IEnergySink IC2, учёт acceptsEnergyFrom и уровня
  напряжения приёмника. API IC2 не встраивается в мод и не нужен без IC2.
- EU → HBM: прямой соседний IEnergySource IC2, учёт emitsEnergyTo, доступной
  энергии и уровня источника.
- Двунаправленные порты автоматически считаются приёмниками, чтобы не
  разряжаться и заряжаться по одному соединению. Выделенная выходная сторона
  EU-хранилища поддерживает отдачу в HBM. FE-хранилище может самостоятельно
  отдавать энергию в FE-порт провода.
- Коэффициент HE:FE берётся из `1.35_conversionRateHeToRF`; для EU используется
  4 FE = 1 EU. Дробное списание округляется вверх: размножения энергии нет,
  возможна потеря менее 1 HE на исходящую операцию.
- Поиск новых внешних портов может занимать до секунды; существующие работают
  каждый тик. Выгруженные соседние чанки не подгружаются для поиска портов.

EU здесь означает API IndustrialCraft 2 Experimental 1.12.2. GregTech EU,
кабели IC2 и другие несовместимые интерфейсы не заявлены поддержанными.
Существующие конвертеры HBM остаются доступны.

## Установка и проверка

Заменять основной JAR Well-Forged, не устанавливать рядом второй HBM/EE.
Сначала проверить копию мира: новую генерацию, открывание двери, радиационный
источник снаружи/внутри закрытого помещения, FE-потребитель и FE-генератор,
EU-потребитель и EU-генератор. Для EU проверить разные стороны машины.
Полная проверка в игре пока не выполнена.

## Сборка

Оригинальная система сборки WF 1.3.2 использует JDK 25, Gradle 9.2.1,
RetroFuturaGradle 2.0.0 и JvmDowngrader для итогового Java 8 JAR.
Команда: `./gradlew build`. Обычный итоговый JAR отличается от `dev` и `java25`.
IC2 API: libs/ic2-api-2.8.221.jar, только compileOnly, официальный источник:
https://maven.ic2.player.to/net/industrial-craft/industrialcraft-2/2.8.221-ex112/

Лицензии исходных проектов сохранены в LICENSE и LICENSE.LESSER.

## Advanced Rocketry и промышленность

Провод подключается к FE-энерговходу многоблочной машины AR. Проверен контракт
LibVulpes; отчёт об отличиях производственных цепочек: EE_PRODUCTION_AUDIT_RU.md.
Обязательного переноса промышленности EE для текущих механик не найдено.

## Выполненные проверки

Полная сборка Gradle завершилась успешно. Итоговый игровой JAR проверен: 3772
класса с байткодом не выше Java 8; API IC2 не встроен. Шесть тестов FE, IC2 и
оригинального FE-адаптера LibVulpes прошли успешно. Расширенные тесты запускались
отдельно через JUnit против скомпилированных классов мода и Minecraft/Forge.
Запуск клиента с пользовательской сборкой, генерация убежища и радиация в мире
пока не проверены. Это сборка P1 для проверки на копии мира.
